# ④ 演習：送料計算のバグを Xdebug で直す

基本操作([③-2](./03-basic-operations.md))を覚えたら、いよいよ実戦です。
**バグの入ったページ**を、Xdebug を使って調査・修正します。

> 対象ページ：http://localhost:8080/exercise （ログイン不要）
> 対象コード：[app/Services/ShippingCalculator.php](../src/app/Services/ShippingCalculator.php)

---

## 仕様（あるべき挙動）

- 小計 = 単価 × 個数 の合計
- **送料：小計が 3,000 円以上なら無料、3,000 円未満なら 500 円**
- 消費税：小計の 10%
- 合計 = 小計 + 送料 + 消費税

## 症状（バグ）

http://localhost:8080/exercise で個数を入れて計算すると、**送料が仕様と逆**になります。

| 入力例 | 小計 | 表示される送料 | 本来の送料 |
|--------|------|----------------|-----------|
| 3 / 10 / 2 | 12,000 円 | **500 円** ❌ | 0 円（無料のはず） |
| 1 / 0 / 0 | 300 円 | **0 円** ❌ | 500 円 |

たくさん買った人が送料を取られ、少ししか買わない人が無料になっています。

---

## 進め方（Xdebug で原因を突き止める）

いきなりコードを直すのではなく、**「どこで値がおかしくなるか」を観察**しましょう。

### Step 1. まず再現する
`3 / 10 / 2` を入力して「計算する」を押し、送料が 500 円になることを確認。

### Step 2. あたりをつけて、送料の計算に踏み込む
送料は `ShippingCalculator::shippingFee()` が決めています。

📍 [ShippingCalculator.php:67](../src/app/Services/ShippingCalculator.php#L67)（`if ($subtotal >= self::FREE_SHIPPING_THRESHOLD)` の行）に ● を置く。

▶ もう一度「計算する」を押す → ここで止まる。

### Step 3. 変数と分岐を確認する
- 「変数」パネルで `$subtotal` を確認 → `12000`
- `F10`（ステップオーバー）で1行進める

✅ ここで**どちらの `return` に進んだか**を見てください。
   `$subtotal`(12000) は 3,000 以上なので `if` の中に入ります。
   その `if` の中で返している値は……？ 仕様（3,000円以上は無料＝0円）と**合っていますか？**

### Step 4. 原因を言葉にする
「小計が3,000円以上のとき、無料（0）にすべきなのに 500 を返している。逆だ」と説明できれば、
原因特定は完了です。

---

## 修正してみよう

原因が分かったら、`shippingFee()` を仕様どおりに直します。直したら再度 `3 / 10 / 2` で計算し、
**送料 0 円・合計 13,200 円**になれば成功です。

<details>
<summary>▶ ヒント（詰まったら開く）</summary>

`shippingFee()` の `if` は「小計が 3,000 円以上」という**正しい条件**を書いています。
でも、その中と外で `return` している値が入れ替わっています。
「3,000円以上 → 無料(0)」「3,000円未満 → 500」になるように、2つの `return` を入れ替えましょう。

</details>

<details>
<summary>▶ 解答（修正コード）</summary>

[ShippingCalculator.php](../src/app/Services/ShippingCalculator.php) の `shippingFee()` を次のように直します。

```php
public function shippingFee(int $subtotal): int
{
    // 3,000円以上は「無料」なので 0 を返す
    if ($subtotal >= self::FREE_SHIPPING_THRESHOLD) {
        return 0;
    }

    // 3,000円未満は 500 円
    return self::SHIPPING_FEE;
}
```

修正前は `if` の中で `self::SHIPPING_FEE`（500）を返し、外で `0` を返していました。
**返す値が逆**だったのが原因です。

### 修正後の確認

| 入力 | 小計 | 送料 | 合計 |
|------|------|------|------|
| 3 / 10 / 2 | 12,000 円 | 0 円 | 13,200 円 |
| 1 / 0 / 0 | 300 円 | 500 円 | 830 円 |

</details>

---

## この演習で練習できたこと

- **症状 → あたり → 該当メソッドで停止 → 変数と分岐を確認 → 原因特定 → 修正 → 再確認** という
  デバッグの一連の流れ
- `if` の**どちらの分岐に入ったか**をステップ実行で目視する技術（[③-2 レッスン6](./03-basic-operations.md)）
- `var_dump` を仕込まずに、値と分岐を確認して原因を突き止める進め方

> ブレークポイントを置いて調べてみましょう。
